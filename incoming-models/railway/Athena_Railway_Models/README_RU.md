# Афина — железнодорожная техника, v1

Девять самостоятельных 3D-моделей в GLB 2.0. Это оригинальные визуальные концепты для цифрового двойника порта, а не копии заводских серий и не инженерные CAD-модели.

## Комплект

| Файл | Модель |

| diesel_industrial_4axle.glb | Промышленный тепловоз, 4 оси |

| wagon_pipe_platform.glb | Платформа со штабелем полых стальных труб |

## Координаты и сборка составов

- Единицы — метры; GLB: Y вверх, +Z вперёд, X поперёк пути.
- Визуальная колея — 1520 мм. В превью внутренние грани головок рельсов расположены на X = ±0,760 м; оси головок ±0,790 м.
- Начало координат — середина машины на уровне основания пути. Верх рельса Y = 0,180 м; центры колёс Y = 0,680 м у локомотивов и 0,640 м у вагонов. Учитывайте это при установке на существующий путь.
- Точки сцепки и расстояние между ними находятся в `connection_points.json` и в `extras` каждого GLB. Сцепки имеют Y = 1,030 м. Для прямого состава расстояние между центрами соседних машин равно половине суммы их `couplerPitchMetres`.
- Геометрия всех деталей записана относительно общего центра машины. Колёса выделены отдельными именованными узлами: перед вращением задайте pivot в центре их локального bounding box, ось вращения X. Колёса не имеют готовых анимационных клипов.
- Грузы имеют имена `cargo_container_0`, `cargo_container_1`, `cargo_coal`, `cargo_pipes`; их можно выключать независимо. Ремни труб — `cargo_straps`. `deck`/`timber_deck` остаются частью вагона.
- У двухсекционного локомотива узлы имеют префиксы `section_0_` и `section_1_`. Межсекционное соединение — отдельный узел. Визуальные внутренние сцепки не задают физическую модель сочленения.
- PBR-материалы встроены. Отдельных текстур, внешних зависимостей и вымышленных торговых марок нет. Контейнеры имеют геометрическую гофру и дверную арматуру, без логотипов линий.

## Веб-сцена

`integration.ts` — небольшой пример загрузки в Babylon.js и установки моделей на прямом пути. Требует существующего проекта с `@babylonjs/core` и `@babylonjs/loaders`; перед созданием камеры и импортом моделей включите правую систему координат `scene.useRightHandedSystem = true`. Если проект уже использует левую систему координат, адаптируйте направление движения вместо переключения существующей сцены.

Для выразительной картинки используйте окружение HDR/IBL, мягкие тени и тональную коррекцию. Стекло здесь непрозрачное отражающее: интерьеров кабин нет. Рендеры показывают сами экспортированные GLB при студийном освещении; рельсы и шпалы добавлены только в сцену превью, в GLB техники их нет.

Модели содержат примерно 52–176 тысяч треугольников каждая (точные числа в `model_statistics.json`). Это вариант для близкого и среднего плана. Для десятков составов в одном кадре понадобятся инстансы, отсечение невидимых объектов и дополнительные уровни детализации. Дальние LOD и запечённые карты нормалей в этот пакет не включены. Работа в конкретном браузере и нагрузка вашей сцены не измерялись.

## Исходники и воспроизведение

Python 3, зависимости: `numpy`, `Pillow`.

```
python build_railway.py
python validate_models.py
```

Рендеры: дополнительно `mitsuba` (проверено на версии 3.9.1):

```
python render_railway.py --kind diesel_shunter_6axle --spp 128
```

`geometry.py` — геометрические функции; `build_railway.py` — полный генератор комплекта; `render_railway.py` — рендер из GLB, не генерация изображений по тексту; `validate_models.py` — структурные проверки.

Проверены заголовки GLB, буферы, индексы, конечность координат, единичные нормали, невырожденные треугольники, согласованность нормалей и метаданные сцепок. Результаты — `validation.json`. Официальный Khronos Validator и импорт в вашу Babylon.js-сцену не запускались. Профиль колёс, тележки, сцепки, оборудование и габариты предназначены для визуализации, а не для расчётов железнодорожной безопасности.

Справка по загрузчику: https://doc.babylonjs.com/features/featuresDeepDive/importers/loadingFileTypes/
